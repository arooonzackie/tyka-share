The spine

A request walks these in order. It can stop at any of them, and stopping is the feature: the ones that cost nothing are the ones that refuse early.

Refuses nothing. It only records, so that no work can happen that the board never saw.

Refuses an unknown lane or profile, and refuses to let a feature claim less ceremony than a feature needs. A question is answered here and the row closes; everything else walks on.

Refuses a card over 1,500 characters, so the restatement of your request cannot quietly become a document. Then it waits for you.

Goal format

Refuses a goal missing any of its five sections, and refuses one whose success criteria name nothing runnable. Prose alone bounces back carrying the complaint.

instant
05

Your approval

Refuses to proceed at all. The single most expensive step in the flow, and it is not the flow: 8 minutes 40 on one approval, against every code gate answering in under a minute.

yours: up to 9 min
06

Checklist shape, then profile floor

Refuses an item that does not say where it may write, what command proves it, and what a pass means. Then refuses the whole list if a full task carries no invariant test and no end-to-end test.

under 5s
07

Dispatch

Refuses a fan-out whose file sets are not provably disjoint. Fresh seats every round, never one long-lived one carrying yesterday's assumptions.

3–12 min
08

Verify

Refuses the word of the thing that wrote the code. Done is what a command proved, and the code runs the command. Green, a bounded retry carrying the failure back, or that one item escalates alone.

Reachability

Walks out from the running entry points only and fails the build when a module or a route exists that nothing in the product can reach. An import from a test file counts for nothing — that is precisely how the escapes stayed green.

The boarding gate, rebuilt

It used to ask whether anything was on the board. It now asks what is being written. Those are different questions, and the old one could not tell “this is a question” from “someone is writing untracked code”.

instant · the old workaround now buys nothing

The loop around it

Every finished run is written up and sent to a reviewer with no access to how it was produced — only the diff, the results, and what was claimed. Ten entries so far.

  • A send gate refuses an entry that carries reasoning, a plan, or anything secret, before it leaves the process. It has refused entries of ours.
  • Verdicts come back and change the code. Six decisions are settled, including two where the reviewer was shown to be wrong and said so.
  • The sharpest rule came from there: assert what a person would see, not the mechanism meant to produce it. Both defects that got through had passed tests asserting a mechanism.

What it still cannot do

It cannot catch two of the five.

A filter that strips a value is invisible to a check that reads imports, and so is a page that returns an error only to a reader without a credential. Claiming five would be the same over-statement the harness was built to refuse.

The write-set contract does not survive contact with the work.

Six times in one night a change landed outside the file set that had been declared for it. Every one was disclosed. Six is not a run of accidents — it says the boundaries are being guessed rather than derived, and that is a planning fault rather than a discipline problem.

Something moves work out of progress, and nobody knows what.

Three times a task set to in-progress was found parked minutes later, mid-run. Each interruption was cheap enough to absorb, which is exactly why it survived three occurrences without being investigated. It is now a defect with a trace attached rather than a note.
